## Goal

A star table for each system and container:
- what each architecture characteristic is now (current) and what it needs to be (needed);
- the gap between the two;
- why;
- which decisions affect it.

The table can compare versions: main, a draft, a git version, or two drafts side by side. This is how planned changes and decisions show their effect.

Ratings come from people. BMO's proposed ratings come in Wave 11.

## Owner requests covered

> - Have a architectural characteristics star rating table that can either be generated by LLM or human inputs. What it currently is and what is needs to be. We could also leverage this to help compare system design decisions and planning decisions to see how planned changes would affect the architectureal characteritics star rating table.

## Design [Proposal; rewritten after the owner answers]

1. **Needed stars.** A `target` (1–5) on each rating entry (★Q9.1).
   - A container without its own target shows its system's, labelled "from the system".
   - Gap = target − rating.
2. **Keep extra keys.** Fix `PUT /api/characteristics` so definitions keep keys such as `measure` and `category`.
3. **The table page** (`p=characteristics`).
   - Scope: a system, a container, or the current selection.
   - Rows: the characteristics, driving ones first. More than 7 driving gives a warning (Q9.4).
   - Columns: Needed ★, Current ★, Gap, Why (the note), Source, and Decisions.
     - Source is a person, or a BMO proposal that was accepted (Wave 11).
     - Decisions lists the decisions that affect it, with their expected impact.
   - Stars are edited in place. The table exports as CSV and Markdown.
4. **Compare.**
   - A version picker on each side: main, a draft, or a git ref. Two drafts can be compared (option A against option B).
   - Each row shows ▲, ▼ or ● for its change.
   - A summary line, for example "This draft: Scalability ▲1, Simplicity ▼1".
5. **Expected impact in decisions** (Q9.2).
   - The decision front matter gets `impacts: [scalability:+1, simplicity:-1]`, checked against the characteristics list.
   - The table shows "expected by ADR-0007" next to the draft's real change.
   - The diff gets a field and a label for it.
6. **Hints** (Q9.3). From Wave 7, for example modularity from D and cycles. Shown as hint chips, never written into the stars.
7. **Overlay.** A "gap" mode for the `@char:<name>` overlay, coloured by needed − current.
