# W0-SPIKE-SHELL — Electron shell with a shared headless TypeScript core

Date: 2026-11-12 · Environment: Linux x64 (sandbox container, root, 2 cores / 7 GB, Xvfb), Node v22.23.4, npm 10.9.9, pnpm 10.28.0

## Question
Can the desktop shell be built as a hardened Electron window that talks to a headless TypeScript core through a narrow IPC bridge, with background work in utility processes and a SQLite cache? Informs accept/reject of **ADR-0003: Electron shell with a shared headless TypeScript core**, and the choice of SQLite binding for the cache.

## Method
All commands run in `spikes/shell/` unless stated.

- Metadata: `npm view <pkg> name version license dist.unpackedSize time.modified --json` for `electron`, `better-sqlite3`, `electron-vite`, `electron-builder`, `@electron/rebuild`, `@electron-forge/cli`, `playwright`; `npm view electron dist-tags`; `npm view electron time`.
- Install: `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install electron@45.3.0 better-sqlite3@13.1.1 @electron/rebuild@4.2.1 playwright@1.65.0` (4 s, 46 packages), then `npx install-electron` to fetch the binary.
- Sizes: `ls -la ~/.cache/electron/*/`, `du -sm node_modules/electron/dist`, `curl -sSIL https://github.com/electron/electron/releases/download/v45.3.0/electron-v45.3.0-darwin-arm64.zip`.
- Prototype: `main.js`, `preload.js`, `index.html`, `renderer.js`, `worker.js`, `bridge.d.ts`. Run: `xvfb-run -a node_modules/electron/dist/electron . --no-sandbox` (full output kept in `runB.log`).
- Playwright: `xvfb-run -a node pw-smoke.js`.
- Bundled Node: `ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron -p "process.versions"`.
- Binary inspection: `nm -D --undefined-only node_modules/better-sqlite3/prebuilds/linux-x64.node`, `file .../darwin-arm64.node`, reading `node_modules/better-sqlite3/lib/binding.js` and `node_modules/electron/install.js`.

## Not verified
- Anything on macOS arm64: launching Electron, window hardening behaviour, `utilityProcess`, loading `better-sqlite3`'s `darwin-arm64.node`, Playwright `_electron`. Only the existence and file type of the darwin-arm64 artefacts was checked.
- macOS packaging: `.app` / `.dmg` size, code signing, notarisation, hardened runtime, whether a `.node` file must be unpacked from `asar` and how `electron-builder` handles it. `electron-builder`, `electron-vite` and `@electron/rebuild` were not run.
- Chromium's OS-level sandbox (all runs used `--no-sandbox` because the process runs as root).
- Windows behaviour of any item.
- CSP delivered as an HTTP response header or via a custom protocol (`protocol.handle`); only the `<meta>` form on `file://` was tested.
- Cancellation of a CPU-bound synchronous task in a utility process, crash recovery, and memory use of utility processes.
- TypeScript compilation of the bridge types; the pnpm workspace layout (the spike used `npm` in an isolated directory).
- Whether the first `install-electron` failure is reproducible, and how pnpm treats a package that needs a separate binary-download step.
- `node:sqlite` stability level in Node 24 documentation; performance comparison between `node:sqlite` and `better-sqlite3`.
- `better-sqlite3@13.1.1` stability: it was published one day before this spike.

## Recommendation
Evidence: on Linux x64, Electron 45.3.0 ran a window with context isolation, the sandboxed-renderer mode, no Node globals in the page, an enforced CSP, blocked navigation and `window.open`, a validated `invoke` round trip, a utility-process worker with progress and cooperative cancel, and a clean exit; the same `better-sqlite3@13.1.1` Node-API binary loaded in Node 22 and in Electron main and utility processes with no rebuild; `node:sqlite` loaded in both runtimes; Playwright's experimental `_electron` API drove the app. Three assumptions did not hold: Electron bundles Node 24.22.2 while the CLI targets Node 22; `better-sqlite3` no longer uses `prebuild-install` or per-ABI binaries; the `electron` npm package has no postinstall download. Interpretation: nothing found here blocks ADR-0003, and I recommend accepting it subject to a macOS arm64 run of `spikes/shell` (without `--no-sandbox`) and one packaged, signed build. The shared core should be tested on both Node 22 and Node 24, since it will run on both. Keep `better-sqlite3` for the cache: the Node-API prebuilds remove the rebuild step, which was the main cost of that choice. Pin an exact version because 13.1.1 is one day old, and keep the storage code behind an interface so `node:sqlite` can replace it once it is no longer experimental on the lowest supported Node. `@electron/rebuild` is not needed for the dependencies tested. The unpacked Linux dist is 274 MB; expect the macOS app to be of a similar order, but measure it.
